# Билеты на горнолыжку — памятка для Claude Code

PWA, которая следит за ценами на прямые рейсы из Москвы на горнолыжные курорты России,
показывает графики и присылает пуш-уведомления. Пользователь говорит по-русски: интерфейс,
сообщения, документация и ответы ему — на русском, коротко, простыми словами.
Работает с Android-телефона (Redmi Note 7, Chrome), компьютер далеко.

Приложение: https://johnlennon000.github.io/ski-tickets/ (корень перенаправляет в `docs/`).
Репозиторий: `JohnLennon000/ski-tickets` (публичный).

## Задача пользователя

Отслеживать цены на билеты из Москвы на курорты на поездку 7–8 ночей в окне 30.01–14.03.2027,
график изменения цены, уведомления на телефон, просмотр с телефона. Бот Aviasales в Telegram
не устроил: не умеет диапазон дат, показывает без багажа и с пересадками, путается в суммах,
нет графика, прислал билет за 8 723 ₽ при фильтре «до 7 000».

Решения пользователя:
- Курорты: Красная Поляна (AER), Эльбрус·Домбай·Архыз (MRV, NAL — можно прилететь в один, улететь из другого),
  Шерегеш (NOZ, KEJ), Хибины (KVK, MMK), Манжерок (RGK), Горный воздух (UUS).
- Сочи и Кавказ — только 8 ночей (два курорта за поездку), остальные 7 или 8.
- Только прямые рейсы, нужен багаж для лыж/сноуборда. 1 взрослый.
- 08.02–21.02 — конференция (даты уточнятся): поездки, задевающие эти даты, собираются, но серые и без уведомлений.
- Пороги (туда-обратно с багажом): Поляна 18 000, Кавказ 17 000, Шерегеш 26 500, Хибины 14 500,
  Манжерок 31 500, Горный воздух 33 000. После смены методики (4.11) цены выросли на 1–2 тыс. — пороги могут потребовать пересмотра.
- Проверка каждые 30 минут. Уведомления — пуш в PWA; Telegram не настроен (необязателен).
- Убран служебный текст из приложения (подвал с пояснениями, ссылки на GitHub); вместо него — страница `#help`.
- Свой домен не нужен.

## Как устроено

```
cron-job.org (каждые 30 мин) ──POST dispatches──▶ GitHub Actions «Проверка цен.» (.github/workflows/check.yml)
   + расписание GitHub "7,37 * * * *" (запасное, срабатывает редко)
python -m tracker:
  api.py      Travelpayouts Data API v3 prices_for_dates (кэш Aviasales), токен — секрет TRAVELPAYOUTS_TOKEN
  market.py   лучший тариф на дату туда/обратно + туда-обратно одной бронью; фильтры (ниже)
  trips.py    поездки по датам и ночам, лучшая по курорту (вне конференции)
  alerts.py   поводы: порог, новый минимум (шаг 1%), −5% к минимуму суток
  push.py     Web Push (pywebpush), ключ VAPID выводится из PUSH_SECRET или TRAVELPAYOUTS_TOKEN; подписки — push/*.json
  checks.py   «Я проверил цену»: checks/*.json → поправка по курорту (медиана за 14 дней)
  store.py    docs/data/{summary.json,best.csv,trips/*.csv}, state/state.json
docs/         PWA: index.html, app.js (без библиотек, SVG-графики), style.css, sw.js, manifest, icons
```

Методика цены (`METHOD = 3` в main.py; при её изменении запомненные минимумы сбрасываются):
- Из ссылки Aviasales: `search_date=ДДММГГГГ` — когда цену нашли; `static_fare_key=…|L0|…` — мест багажа
  (L0 — без багажа). `L` как «багаж» — догадка по данным, не подтверждена документацией.
- Цены старше `max_price_age_days: 3` отбрасываются (в первой проверке ~891 из ~1 900).
- Доплата за лыжи 2 500 ₽ за перелёт (сверено вручную: с багажом дороже ≈ на 2 400); если `L≥1` — 0.
- Обратные рейсы с вылетом 0:00–6:00 не учитываются (`night_returns: false`).

## Что проверено, а что нет

Проверено: `python -m pytest -q` (18 тестов), живые запуски на GitHub, пуш на настоящий телефон
(пришло «Уведомления включены» 1.11), установка PWA на Android, офлайн, cron-job.org (ответ 204).

Не проверено / открыто:
- **Подписка телефона пропала 4.11 05:01** (push-служба ответила 404/410, файл удалён сервисом, `state.push.known` пуст).
  Пользователю нужно заново: в приложении «Включить уведомления» → «Открыть GitHub» → «Commit changes».
- Нажатие на уведомление, утренняя сводка на телефоне — не подтверждены пользователем.
- Кнопка «Я проверил цену» в живую не использовалась.

## Поиски других источников цен (итог)

- Живой поиск Aviasales через API — только крупным партнёрам. Сайт aviasales.ru и Яндекс Путешествия —
  защита от ботов. Партнёрские программы Travelpayouts (Tutu, Яндекс…) дают ссылки, не цены.
- Сайты авиакомпаний, проба 4.11 через телефон пользователя (Tailscale exit node, выход RU,
  `.github/workflows/probe.yml`, результаты в `probe/`): Победа открывается; Аэрофлот, S7, ЮТэйр,
  Уральские — блокируют автоматический браузер. Маскировку робота не делать.
- Разбор внутреннего поискового API сайта Победы был запрещён системой безопасности; без явного
  письменного разрешения пользователя («разрешаю разбирать сайт Победы») не делать. Риск: блокировка
  домашнего адреса, через который ходит и «Дозор билетов» (РЖД).
- Предложено, не решено: API Яндекс Расписаний (бесплатный, только расписание без цен) — показывать,
  что рейс существует, даже когда цены в кэше нет.

## Правила

- Секреты только в GitHub Secrets (`TRAVELPAYOUTS_TOKEN`, `TS_AUTHKEY`, по желанию `PUSH_SECRET`,
  `TELEGRAM_BOT_TOKEN`). Ничего секретного в репозиторий: он публичный.
- Расписание GitHub привязано к последнему, кто менял `check.yml`: правки от Claude-приложения его «отвязывают»;
  если запуски по расписанию пропадут — попросить пользователя сделать любую правку файла самому
  (основной запуск всё равно идёт от cron-job.org).
- Push: `sub` в подписи VAPID — https-адрес **без пути** (py_vapid иначе не подписывает).
- Service worker берёт файлы с `cache: "no-cache"`, иначе GitHub Pages отдаёт старую копию до 10 минут.
- Не путать с проектом «Дозор билетов» (`JohnLennon000/bilet-dozor`, РЖД и самолёт Бугульма → Москва).
  Общий только телефон-выход Tailscale (`redmi-note-7-1`), который «Дозор» использует каждые 10 минут.
